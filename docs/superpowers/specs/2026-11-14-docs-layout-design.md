# 介紹站改成文件站版型

日期：2026-11-14　前一份：`2026-11-14-kit-packs-site-design.md`

## 為什麼

Jeff 看了上線的站，說版面要「學 UnoCSS / Tailwind 那種網站」。問他重點是首頁氣勢還是內頁好查，
回答「基本上應該是 2（內頁好查）比較多」。

## 目標

- 內頁（套組頁、kit 頁）變成文件站：左側欄列出所有套組與 kit，中間內容，右邊本頁目錄。
- 任何一頁都能搜尋（Ctrl+K 或 `/`），打「金流」「上傳」直接跳到套組或 kit。
- 程式碼有語法上色；README 裡的程式碼區塊也有複製鈕。
- 深淺色跟系統，可手動切換並記住。
- 首頁換到同一個外框：置中標題、可複製的指令、套組卡、kit 清單。

## 不做

- 首頁的分頁切換展示區（Jeff 說重點在內頁；之後要再加）。
- 換 VitePress。資料管線、私有過濾、不公開字詞檢查都留著。
- 文案。新增的字只有介面標籤（搜尋、本頁內容…），都在 `site/copy.json`。

## 做法

考慮過三種：

1. **留著自己的產生器，只換版型**（採用）。安全檢查與測試原封不動，新增的東西都是純函式。
2. 換 VitePress。現成的搜尋與側欄，但私有過濾與洩漏檢查要重接，而且多一整套依賴。
3. 瀏覽器端載上色函式庫。會多一個外部請求、上色前會閃一下，而且上色後的字不會經過洩漏檢查。

語法上色因此改在產生時做（`site/highlight.js`，零依賴）：只認註解、字串、關鍵字、shell 變數，
認不得的語言照原樣輸出。不上色數字 —— 把 IP 位址切成幾段標籤會讓洩漏檢查看不到它。
保險起見 `scanLeaks` 也改成另外掃一次「去掉標籤後的文字」。

## 檔案

| 檔案 | 職責 |
|---|---|
| `site/escape.js` | `escapeHtml`（從 md.js 搬出來，避免循環相依） |
| `site/highlight.js` | `highlight(code, lang)` → 已跳脫、帶 `tk-*` span 的 HTML |
| `site/md.js` | 程式碼區塊帶語言與上色；標題帶 `id`（同頁重複的加 `-2`） |
| `site/search.js` | `buildSearchIndex(model, copy)`、`searchScript(entries, clientSource)` |
| `site/search-client.js` | `rank(entries, query)`；瀏覽器與測試共用 |
| `site/shell.js` | 外框：頁首、側欄、目錄、搜尋視窗、頁尾、複製框 |
| `site/render.js` | 三種頁面的內容，交給 shell 包起來 |
| `site/style.css`、`site/app.js` | 版型；複製、深淺色、手機側欄、搜尋、目錄跟隨捲動 |

站上多一個檔 `assets/search.js`（搜尋資料 + 比對函式）。搜尋資料只來自已過濾的 model，
所以私有 kit 不會出現；它也跟其他檔案一樣要過不公開字詞檢查。

## 邊界

- 沒有 JavaScript：側欄、目錄、連結照常可用；搜尋鈕與深淺切換不作用。
- 手機：側欄收成抽屜，目錄隱藏。
- README 沒有任何標題：目錄只列「安裝」「說明」。
- 搜尋字串空白：不顯示結果。找不到：顯示一行說明。
